### まず、3 つの不変条件(約束を強制される性質に変える)

このプランのバグのほとんどは、3 つの欠けている不変条件のインスタンスです。これらを最初に構築し、個別の修正はその上に載せます。

- **INV-1. ゲートの結果の契約。** すべてのゲートと外部レビューに、型付きの結果を一つ与えます: `ran(findings) | not_run(reason) | unavailable(reason)`。「合格」には、チェックが実行されたという積極的な証拠が必要です。すべての Codex の呼び出し箇所は `lib/outside-review-result.ts` を経由し、テキスト、stderr、終了ステータスを受け取ります(B1)。無料のリントは、`gstack-learnings-search` と `gstack-timeline-read` の `2>/dev/null || exit 0` を失敗させ、明示的なゲートのバイナリの一覧を `|| true` で包んだ呼び出しも失敗させます。それ以外の、ベストエフォートの末尾処理には、同じ行に理由を書きます。
  - **状態。** `not_run` は、gstack がチェックを実行しないと決めたことを意味します(計画が束縛されていない、機能が無効、前提条件が意図的に欠けている)。`unavailable` は、試みたが実行できなかったことを意味します(サンドボックス、廃止されたモデル、バイナリが死んだ、bun がない、ネットワーク)。このウェーブで追加または変更されるすべての結果は、`docs/troubleshooting.md` の表で一つの状態、理由コード、修正のアクションに対応します。
  - **ユーザーに見えるもの。** `ran` 以外のすべての結果は、一行を表示します。`<gate>: not run (<reason>). Fix: <command>` または `<gate>: unavailable (<reason>). Fix: <command>`。実際の値(終了コード、パス、ホスト)を入れます。既存の機械的なマーカー(`OUTSIDE_STATUS`、`CODEX_MODE`、`DESIGN_READY`)は、名前を変えません。
  - **呼び出し側の動作。** 新しい `classifyOutsideReview({text, stderr, exit})` は、三つの別々のフィールドを返します。実行(`ran | unavailable(reason)`)、指摘(最も高い重大度、またはなし)、判定(`clean | findings | unverified | unavailable`)。`validateOutsideReview` はラッパーとして残し、`claude-code/SKILL.md.tmpl:130,198,268` の三つの直接の import 元が動き続けるようにします。2 引数の CLI の形式は、今日の終了コードをそのまま保ちます(0 完了、1 利用不可、2 使用法の誤り)。なぜなら `lib/` はチェックアウトから直接動き、古いレンダリング済みのスキルは `|| exit 1` でそれを呼ぶからです。`--verdict`(`--stderr` または `--exit` によって暗黙に指定される)を付けると、`VERDICT: ...` を出力し、0 / 3 / 4 / 1 で終了します。生成されるすべての呼び出し側は、同じコミットでこの形式に移り、明示的に分岐します。`unverified` は、重大度のタグも明示的な「指摘なし」の行もない、完了した構造化レビューを扱います(/codex review の既存の UNVERIFIED 状態)。/codex consult と challenge は、新しい `execution` ゲートを使います。このゲートは、実行の証拠だけを確認し、レビューのマーカーは確認しません。理由コードは `lib/gate-outcomes.ts` に置き、バリデーターと、トラブルシューティングのアンカーのテストが import します。テストでは、古いレンダリング済みの呼び出し側を新しい lib に対して実行します。/ship と /review は、`unavailable` をカバレッジの欠落として扱います。処理を続け、準備状況のダッシュボードと PR の本文にそれを表示し、合格としては決して数えません。P0/P1 の `findings` 判定は、ネイティブの P0/P1 と全く同じようにブロックします。実際の CLI と生成された呼び出し側を一緒に通してテストします。
- **INV-2. 書き込み、検証、そして刻印。** ストレージは、作業が完了したと印を付けるのは、それが保存されたことを確認した後だけです。対象は、メモリの取り込み(A1)、デザインのバリアントのラウンド(F4)、学習内容/質問のログ(G3)です。「ステージ済み」「公開済み」「インデックス済み」は、別々の状態です。
- **INV-3. ホストのコンフォーマンステスト(無料のスイート)。** `usesEnvVars: true` のすべてのホストについて、レンダリングされたすべての SKILL.md とセクションのファイルを生成し、すべての囲まれた bash ブロックに `bash -n` を実行し、各ブロックのルート解決の行を、新鮮な `env -i` 風のシェルで、スタブのバイナリを持つ一時的なインストールルートに対して実行します。どのホストでも、展開が空の場合、または `/bin/`、`/browse`、`/design`、`/gstack-` で始まるパスがある場合は失敗させます。Codex の SKILL.md がシンボリックリンクの場合は失敗させます。どのホストの SKILL.md も 160,000 バイトを超える場合は失敗させます。同じスイートの生成 bash のリントは、二重引用符の中の `~/` パス、およびテンプレートのない `mktemp` または `${TMPDIR:-/tmp}` テンプレートを使わない `mktemp` で失敗させます。どちらも今日の origin/main で失敗します。詳細: インストールレベルのチェックは、既存の `test/host-conformance.test.ts` を拡張します(codex、kiro、factory、opencode、cursor、copilot: インストールされた SKILL.md のどれもシンボリックリンクでないこと、design/make-pdf の dist が存在すること、すべてのセクションのポインターが読み取り可能なファイルに解決されること)。レンダリングレベルのチェックは、10 の環境変数ホストすべてを、1 つの新しいテストでカバーします。このテストは、ホストごとに一度レンダリングします。`GSTACK_*`、`$B`、または `$D` を使うすべてのフェンスには、共有のプレリュードをちょうど一回含める必要があります。プレリュードは `env -i` と `set -u` の下で、スタブのバイナリとともに、B/D の利用者を含めて実行します。リントは、引用符をトークン化し、次の場合に失敗させます: `~/` の語が二重引用符の中にある場合。`mktemp` にテンプレートがない場合、または `/tmp/` の固定のテンプレートの場合。同じフェンス内で代入されていない変数に対して `cd`、`rm -r*`、`mv`、または `git -C` を使う場合(ただし `cd -- "${VAR:?...}" || exit 1` と書かれている場合を除く)。リントとサイズのゲートは、すべてのホストのレンダリングで実行します(Claude を含む)。サイズは UTF-8 のバイト数で数えます。
