### リリースの約束(ゴールライン)

- **P1. 古いマシンは、ワークフローをサイレントに実行できない。** セッション開始時に、領収書付きの fetch で `origin/main` が進んでいることが示された場合、チェックアウトは(autostash 付きで。決して reset はしない)自分自身を fast-forward し、setup を更新し、`--check` を再実行する。トレーラーが `fail` の間は、ワークフローの実行を拒否する。契約の下限より下では、オフラインでも拒否する。下限より上では、オフラインのマシンは目に見える古い注記を付けて実行する。Capy の autoplan ドライバー自身は、最初の `next` で doctor を実行し、`fail` のトレーラーを拒否する。1.91.12 のチェックアウトは、スレッドが使う全マシンで、1回の `install.sh --check` で最新に達する。サブエージェントの最初の報告には `gstack:` のトレーラーが含まれる。
- **P2. インストーラーとチェックは一致する。** `gstack-capy-install` は、次の新しいシェルでの `--check` が失敗するマシンで、決して `gstack: ok` を表示しない。`GSTACK_LAUNCH` は検証済みの Bun を `PATH` に載せる。lib のコードは、`bun` を名前で起動しない。
- **P3. 3回改訂の無人 autoplan の実行が、検証を通って完了する。** 改訂ごとのスコープの決定 ID、Capy のサブエージェントとして実行されたフェーズのための `submit --result --extract` と `--outcome`、どの再実行もディスパッチできる前に同じ実行内で `revise --plan v2`、明示的にリンクされた繰り返しのみを重複排除する再実行、機械的に一致するボイスに従うユーザーへの異議のデフォルト(ただし `all` がオーナーの方向性をひっくり返すことはない)、回答の出所情報、変更されたファイルからのスコープ、すべてのフェーズに先行フェーズの合意を与えること(推移的な無効化を伴う)、そしてコンパクトな Capy のドライバーのドキュメント。
- **P4. プランの義務は、レーンが完了を報告する前に機械的なゲートに届く。** さらに、プランが名指しするすべての有料ゲートは、承認の前に、宣言されたアダプターの構造化されたプランから価格を付けられる。アダプターのないゲートは、オーナーが回答できる `GATE_UNPRICED` 項目となり、黙って受け入れられることはない。リリース1では gstack のアダプターのみを出荷する。他のランナーのマニフェストは `not configured` と報告する。
- **P5. Stamp-at-merge は、CI が確認しているのがリポジトリ自身のスクリプトである場合に、そのスクリプトに委譲する。** stamp-only の証明はツリーの領収書から得る。マイグレーションの衝突検出と、push の前および pre-push フック内で実行される封印された出力のガードを伴う。

rule=allow` と表示します。受領記録は、受信側のリモート、送信対象の ref とオブジェクト ID、ポリシーのハッシュ、スキャナのバージョンに紐づけます。スキャン対象の履歴から除外されるのは、その送信先に存在することが確定したコミットだけです。そのため、新規または未知の送信先への push は、到達可能な履歴全体をスキャンするか、`incomplete` になります。staged を出力し、封印された内容のスニペットは含めません。すでに公開された履歴は、自動の force-push ではなく、非破壊的な調査の案内とともにオーナーに回します。`hook` モードは、`lib/prepush-refs.ts` を通じて pre-push の stdin から ref を読みます。`/ship` は `git push` の前に `--range `gstack-pregate run --only sealed --range origin/<base>..HEAD` を実行すること。レーンは、現行の `SEALED:` 合格または `not configured` の結果がない限り push しない。その行を、`GSTACK_RESULT` の後の引き継ぎに貼り付けること。」(今回の情報漏えいは `/ship` - `bin/gstack-upgrade` は、session-update から抽出した、読み込まれるライブラリの上にある bash。競合からの回復はバイトとスタッシュを保持する。`--to` はタグとコミットを区別し、対象を検証する。busy の判定は、呼び出し元の祖先の外にあるライブのインストールリースと、インストーラの flock とする。ラッパーは、マージ、setup、check の前にサポート対象の Bun を先頭に追加する。
- 古いチェックアウトは、ローカルの bare origin を `GIT_ALLOW_PROTOCOL=file` と無効なプロキシのもとで depth-1 でクローンして合成する。シミュレータの環境はアローリストで、センチネルのテストを持つ。フィクスチャは、シナリオが許す場合は 1 つのアップグレード済みチェックアウトを共有する。
- lib の spawn と生成されるフックは `process.execPath` を使う。`test/bun-spawn-ratchet.test.ts` がこれを守る。
- 指摘の行は `attempt` を持つ。リビジョンをまたぐ参照は attempt で修飾する。決定の参照は、リビジョンを認識する 1 つのコンストラクタを通す。`Scope.ui` は `yes|no|unknown` とし、revise は `REVISE_SCOPE_CHANGED` とともにスコープを再検出する。
- `revise` は Implementation のバイトだけを置き換え、義務を検査し、冪等な再開を伴う、ジャーナル付きの世代遷移を実行する。変更された入力の推移的な利用者を無効化する。`PLAN_SHAPE_PARTIAL` は scaffold の案を置き換える。
- B9 の合意ルールは機械的である(`user_challenge` と解決トークンの両方が重なる、または `agreement` の上書き)。
- 数値の行は、`[measured]`/`[estimated]`/`[target]`/`[fixture]` のタグと `file:line` の受領記録を持つ、単位を伴う数値に限定する。実在性と価格のチェックは、永続化された検証の境界として実行する。
- `manifests` は、シャードランナー自身のインベントリを gstack アダプタとして取り込み、それ以外では `not configured` と報告する。`goldens` は既存の `regen` のために削除する。タスクは `checks[]` を持つ。受領記録は目的と選択によってバージョン付けする。Docker の義務は、一致するジョブの受領記録によってのみ解消される。
- `--gate` は、新しい `--list --json` の計画を消費する。引用は入力に紐づける。`GSTACK_EVAL_DRY_RUN` は無し。
- stamp のみの証明は、ツリー受領記録と、生のツリーエントリ比較を伴う 1 つの `migration-number` ルールである。比較に失敗した場合は `incomplete` とし、stamp のみとは決して扱わない。stamp のチェックは明示的な証拠源を取る。委譲された stamp は、独立した事後条件を持つ不変の前ツリーと比較する。migration の census はページ分割され、SHA に紐づき、不完全な場合は拒否する。
- 封印チェックは、デコード前に送信される各 blob のバイトを検査し、ルール文法を制限するか、正規表現の時間を予算化する。`--allow-repo-commands` なしでポリシーを読み、受領記録を送信先、ref、オブジェクト、ポリシー、スキャナのバージョンに紐づけ、スニペットなしでオブジェクトの識別子を出力する。フックは `lib/prepush-refs.ts` を共有する。
- 公開する対象は、名前付きラベルの下で、唯一のブートストラップの例外を伴って egress を受領記録として残す。`review-record.md` は、sha によって束縛された記録へリンクする。ブートストラップは、session-update とまったく同様に、egress lib に対してフェイルオープンとする。
