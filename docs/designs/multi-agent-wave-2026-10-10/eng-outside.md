21. **[重大度: 中] 共有のコマンド契約が、内部で一貫していない。** B0 の「すべての終端行」の規則は、主な出力がスキーマ、解析された JSON、または doctor のトレーラーであるコマンドと矛盾します。B7 は、ステータスの不一致に、終了コード 2 と終了コード 1 の両方を割り当てています。C1 は `.json` ファイルにコメント付きの例を提案していますが、C2 が読むキューのモードのキーを省いています。また B0 は、構造的な妥当性と、完了した実行を混同しています。まずスキーマと、コマンド/ステータス/終了コードの対応表を公開してください。その中には、`gate_pending`、部分的な回答、中断された実行、JSON だけのエラーを含めてください。[docs/test-value-bar.md:23](/workspace/gstack/docs/test-value-bar.md:23) が求めるとおり、ワイヤー契約の検証は厳密に行い、ワークフローの文面は振る舞いとしてテストしてください。

22. **[重大度: 中] 納期の見積もりと検証の順序が、必要な作業の大部分を含んでいない。** PR B には、ランナー、クラッシュからの回復、プロバイダーのアダプター、スキーマの移行、ゲートの解析、プロンプトの削減が含まれます。PR C には、トランザクション的な変更、キューの調整、証拠の移植性、依存関係の分析が含まれます。そのため、どちらも、示された少ないライブラリ数では裏付けられません。検証にも、CI が明示的に実行するテストコードの型のラチェットが抜けています([.github/workflows/free-tests.yml:223](/workspace/gstack/.github/workflows/free-tests.yml:223))。B と C を、これらのコンポーネントごとに見積もり直してください。任意の広がりは、明示的な階層の背後に移してください。最終的な受け入れの順序の前に、ビルド、認証情報のスキャン、適用可能な整形、選択された品質ジャッジを追加してください。凍結されたツリーでの最終的な無料スイートの実行は維持し、プラットフォームとプロバイダーのカバレッジが不完全な場合は、別に報告してください。

テスト計画の不足点:

- **有料の完了の後にプロセスが死ぬ場合:** `test/autoplan-run-recovery.test.ts` を追加します。結果の永続化の前後でランナーを殺し、自動的な二重課金が起きないことを検証します。
- **`resume`、`answer`、`ack` の同時実行:** `test/autoplan-run-concurrency.test.ts` を追加します。排他的な所有権、リビジョンの競合、正確に 1 回の確認応答の計上を確認します。
- **回答がレビュー済みのアーキテクチャを変える場合:** `test/autoplan-answer-invalidation.test.ts` を追加します。影響を受けるフェーズだけが開き直され、古い返信では一切書き込みが起きないことを証明します。
- **構造化された出力がレビュー担当者の指摘を漏らす場合:** `test/headless-artifact-integrity.test.ts` を追加します。重複 ID、循環、不正な末尾、トラバーサル、シンボリックリンク、未知のスキーマのバージョンを含めます。
- **取り込んだ証拠が VM の破棄後も残る場合:** `test/evidence-bundle-portability.test.ts` を追加します。元のオブジェクトデータベースやログがない、新しいクローンから検証します。
- **バージョンだけの編集がゲートに影響する場合:** `test/tree-receipt-stamp-sensitive.test.ts` を追加します。バージョンに依存する生成出力と、ロックファイルのメタデータと依存関係の変更を比較します。
- **最後のキューの確認の後にベースが動く場合:** `test/gstack-restamp-queue.test.ts` を拡張します。同時のコーディネーターと、検証からマージまでの間の移動を含めます。
- **リリースコマンドが宣言されていない状態を変更する場合:** `test/restamp-command-boundary.test.ts` を追加します。ドライランの副作用、ロールバックの競合、ミラーの部分的な完了を含めます。
- **API/ホストのサブエージェントが、使用可能なカバレッジなしに完了を主張する場合:** `test/outside-runner-contract.test.ts` を追加します。入力の欠落、切り詰め、拒否、未知のファミリー、終端の証拠の欠落を検証します。

失敗モード:

| 失敗モード | 検出 | 対応 | テスト |
|---|---|---|---|
| プロバイダーは完了したが、完了レコードがない | ディスパッチされた試行に終端のレシートがない | 実行を不明とし、照合する | `autoplan-run-recovery` |
| 2 つのプロセスが 1 つの実行を再開する | 実行の所有権/リビジョンの競合 | 2 番目の書き込み側を拒否する | `autoplan-run-concurrency` |
| 返信が古いゲートを対象にしている | 期待されるリビジョンの不一致 | 書き込みなしで拒否する | `autoplan-answer-invalidation` |
| 成果物の集約が指摘を落とす | レビュー担当者 ID の照合 | 不完全とマークする | `headless-artifact-integrity` |
| レシートが消えた Git オブジェクトを参照する | バンドルの完全性チェック | 再利用を拒否する | `evidence-bundle-portability` |
| バージョン変換がゲートの振る舞いを変える | ゲートごとの同等性チェック | スタンプ済みツリーで影響するチェックを実行する | `tree-receipt-stamp-sensitive` |
| マージ中にキューが変わる | 条件付きマージの拒否 | 割り当てと統合ツリーを再計算する | `gstack-restamp-queue` |
| リリースフックが部分的に書き込む、またはミラーが失敗する | ジャーナルと出力の比較 | 再開するか、競合を認識したロールバックを行う | `restamp-command-boundary` |
| 事前ゲートが動的な依存関係を見逃す | 未サポートのマッピング/依存関係の宣言 | 保守的なカバレッジを選ぶ | `pregate-selection` |
| 必須のリモートレーンが実行されない | 必須レーンのレシートの照合 | 公開をブロックする | `pregate-invalidation` |
| ワーカーが予約済みの支出を抱えたまま死ぬ | 決済されていない試行のレコード | 予約/不明な請求を保持する | `spend-ledger` |
| 無人セッションが同期の同意を引き継ぐ | egress の入口でのセッションポリシー | 同期を明示的にスキップする | `gstack-skill-start` |
| 要求されたインストールのリビジョンが異なる | 解決されたコミットの比較 | ピンが満たされないことを報告し、更新しない | `gstack-capy-install` |
| ロールバックが、その後のユーザーの編集に遭遇する | 現在のバイト列が postimage と異なる | 競合で停止し、編集を保持する | `restamp-command-boundary` |
