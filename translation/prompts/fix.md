# 翻訳レビューの指摘を適用する手順(Haiku 作業者向け)

指摘の一覧は、指示で渡される JSONL ファイルに 1 行 1 件で書かれている。フィールド: `file`, `line`(目安。ずれていることがある), `kind`, `severity`, `ja`(抜粋), `en`(原文), `fix`(修正案)。

各指摘について:
1. `file` を Read し、`ja` の抜粋を手がかりに該当箇所を見つける(見つからなければ Grep で探す)。
2. 必要なら原文を `git show upstream/main:<file>` で確認する。
3. `fix` のとおりに、自然な日本語で修正する(Edit で最小限の置換。置換前の文字列が 1 箇所だけに一致することを確認する)。段落の抜けは原文を訳して補う。用語の統一は同じファイル内で揃える。
4. 次の場合は修正せず「スキップ」として理由を報告する: 抜粋が見つからない、修正案が文脈に合わない、コードブロック・コマンド・識別子・`{{...}}`・`${...}`・英語トークンの見出し(例 `## Preamble (run first)(…)`)を変える必要がある、`fix` が具体的でない。

してはいけないこと:
- 生成された `.md` を編集しない。同名の `.md.tmpl` がある場合は必ず `.tmpl` を編集する。
- 日本語の見出しを英語に戻さない(テストが日本語の見出しを固定していることがある)。
- `bun run gen:skill-docs`、`git add`、`git commit`、`git stash` を実行しない。指摘されていない箇所を書き換えない。英語のトークン、コマンド、パス、数値を変えない。

最後に、適用した件数と、スキップした指摘(file:line と理由)を箇条書きで報告する。
