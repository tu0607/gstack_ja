# 翻訳セルフレビューの手順(Haiku レビュアー向け)

リポジトリ: garrytan/gstack の日本語版フォーク。担当ファイルの一覧は、指示で渡されるチャンクファイルに 1 行 1 パスで書かれている。

各ファイルについて:
1. 日本語版(現在の作業ツリー)を Read で読む。
2. 英語の原文を `git show upstream/main:<path>`(指示で別の参照が与えられた場合はそれ)で読む。大きいファイルは `| sed -n 'A,Bp'` で分割してよい。原文が存在しない場合は日本語版だけを読む。
3. 段落ごとに突き合わせ、次の種類の問題だけを報告する:
   - `mistranslation`(誤訳): 意味が原文と異なる、否定・条件の反転、主語や対象の取り違え、数値・識別子・フラグ名・パスの欠落や変化、文や段落の抜け。
   - `untranslated`(未翻訳): コードブロックやコマンド以外で、英文がそのまま残っている段落や文。
   - `syntax`(構文): Markdown の壊れ(リンクの破損、表の列ずれ、閉じていないフェンス、`**` やバッククォートの対応崩れ)、テンプレートの `{{...}}` やリゾルバーの `${...}` の破損。
   - `token`(トークン破損): コマンド、識別子、環境変数、パス、英語トークンを残すべき見出しの英語部分が変わっている。
   - `unnatural`(不自然): 明らかに日本語として壊れている場合だけ(機械翻訳調で意味が取れない、用語がファイル内で食い違う)。軽微な文体の好みは報告しない。
4. 報告は JSONL(1 行 1 件)で、指示された出力ファイルに Write で書く。フィールド: `file`, `line`(日本語版の行番号), `kind`, `severity`(`high`|`medium`|`low`), `ja`(問題の箇所の抜粋、80 文字以内), `en`(原文の対応箇所、80 文字以内。無ければ空), `fix`(具体的な修正案の日本語、1 文。「判断が必要」だけの報告はしない)。
   - `high`: 誤訳・構文・トークン破損で、読者の行動や生成物が変わるもの。`medium`: 意味は通るが誤解を招く。`low`: 不自然さ。
   - 1 ファイルあたり最大 40 件。問題が無いファイルは報告不要。

してはいけないこと: リポジトリ内のファイルを編集しない(Write は出力ファイルだけ)。`bun run gen:skill-docs`、`git add`、`git commit`、`git stash` を実行しない。コードブロック内のコマンドやサンプル、test/fixtures は翻訳対象外なので、英語のままでも報告しない。

最後に、担当ファイル数、読んだファイル数、件数(severity ごと)を 3 行で報告する。
