# 差分翻訳の手順(Haiku 作業者向け)

リポジトリ: このチェックアウトは garrytan/gstack の日本語版フォーク。upstream の変更を日本語版に取り込む。
担当ファイルの一覧は、指示で渡されるチャンクファイルに 1 行 1 パスで書かれている。各行の先頭に `DIFF ` または `FULL ` のモードが付く。

## モード
- `DIFF <path>`: 日本語版がすでにある。英語の差分 `translation/pending/<path>.diff`(基準 → upstream の unified diff)を読み、日本語版の対応箇所だけを更新する。追加された行は訳して挿入し、削除された行は日本語版から消し、変更された行は訳し直す。差分の位置は見出し・前後の文・コード行を手がかりに探す(行番号は日本語版とずれている)。
- `FULL <path>`: 新規ファイル、または日本語がまだ無いファイル。`git show upstream/main:<path>` の全文を訳して、そのパスに書く(ファイルが無ければ新規作成)。

## 翻訳ルール
- 自然で簡潔な日本語(です・ます調)。英語の語順の直訳や機械翻訳調を避ける。同じファイル内で用語を統一する。
- 訳さないもの: コードブロック(```〜```)、コマンド、スクリプト、サンプルコード、ファイルパス、識別子、環境変数、フラグ、URL、`{{...}}` と `${...}` のプレースホルダー、JSON のキー、frontmatter のキー(`name:`、`triggers:` の値など機械が照合するもの)。
- 英語トークンを残す見出し・ラベル: 製品コードやテストが読むもの。すでに `## Preamble (run first)(プリアンブル。最初に実行)` のように「英語トークン(日本語)」の形になっている見出しは、その形を保つ。原文で新しく増えた見出しは、同じファイルの既存の見出しの書き方に揃える(英語+括弧の形が多い節ではその形、完全に日本語の節では日本語)。迷ったら英語トークンを残して日本語を括弧で添える。
- 特に残すもの: `# gstack: design-md-format=spec`、`## currentDecision (…)`、`## Review Sections(…)`、`## Implementation plan`、`## Review record`、`**STOP.**` と `Read \`<path>\``、`Recommendation: … because …`、エラー文字列そのものの見出し、Codex など外部モデルへ送るプロンプト本文、`RESULT FORMAT` など機械が読む書式。
- 記号: 括弧・コロン・疑問符は半角(`(`、`)`、`:`、`?`)。英数字と日本語の間は半角スペース 1 つ(例: `Aside を`、`3 回`)。
- 角括弧の直後に丸括弧を続けない(`[名前] (理由)` のように空白を入れる。続けるとリンク構文になる)。
- Issue 番号で行を始めない(`#1234 で…` は見出しになる。`Issue #1234 で…` と書く)。
- `.md.tmpl` がある `.md` は生成物なので編集しない(`.tmpl` 側だけを編集する)。
- TypeScript(scripts/resolvers など)は、テンプレートリテラル内の散文だけを訳す。コード、コメント、`${...}` 式、正規表現、文字列のキーは変えない。
- JSON(`*/sections/manifest.json`)は値の散文だけを訳し、キーと構造は変えない。

## してはいけないこと
- `bun run gen:skill-docs`、`git add`、`git commit`、`git stash`、`translation:mark` を実行しない。
- 担当外のファイルを編集しない。test/fixtures/** を編集しない。

## 報告
最後に、ファイルごとに「適用した差分のハンク数(DIFF)または訳した行数(FULL)」と、判断に迷って原文のまま残した箇所(file:line と理由)を箇条書きで報告する。
