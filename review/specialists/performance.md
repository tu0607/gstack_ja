# パフォーマンス・スペシャリストのレビューチェックリスト

適用範囲: SCOPE_BACKEND=true または SCOPE_FRONTEND=true の場合
出力: JSON オブジェクト。1 行に 1 件の指摘。スキーマ:
{"severity":"CRITICAL|INFORMATIONAL","confidence":N,"path":"file","line":N,"category":"performance","summary":"...","fix":"...","fingerprint":"path:line:performance","specialist":"performance"}
任意: line, fix, fingerprint, evidence, test_stub。
指摘がない場合: `NO FINDINGS` とだけ出力する。

---

## カテゴリ

### N+1 クエリ
- ループの中で ORM の関連をたどっているが、事前読み込み(.includes、joinedload、include)をしていない
- 反復処理のブロック(each、map、forEach)の中でデータベースに問い合わせており、まとめられる
- 遅延読み込みの関連をトリガーするネストしたシリアライザー
- GraphQL のリゾルバーがフィールドごとに問い合わせており、バッチ処理されていない(DataLoader の使用を確認する)

### データベースのインデックス不足
- 新しい WHERE 句が、インデックスのないカラムを使っている(マイグレーションファイルやスキーマを確認する)
- インデックスのないカラムに対する新しい ORDER BY
- 複合的なクエリ(WHERE a AND b)に、複合インデックスがない
- 新しく追加された外部キーのカラムにインデックスがない

### アルゴリズムの計算量
- O(n^2) 以上のパターン: コレクションに対するネストしたループ、Array.map の中の Array.find
- ハッシュ、マップ、セットでの参照に置き換えられる、繰り返しの線形探索
- ループ内での文字列連結(join や StringBuilder を使う)
- 1 回で済むのに、大きなコレクションを複数回ソートやフィルターしている

### バンドルサイズへの影響(フロントエンド)
- 既知の重いプロダクション依存関係を新たに追加している(moment.js、lodash の全体、jquery)
- バレルインポート(import from 'library')を、深いインポート(import from 'library/specific')にせずに使っている
- 最適化されていない大きな静的アセット(画像、フォント)をコミットしている
- ルート単位のチャンクにコード分割がない

### レンダリングのパフォーマンス(フロントエンド)
- フェッチのウォーターフォール: 並列化できる API 呼び出しを逐次に行っている(Promise.all)
- 描画のたびに新しいオブジェクトや配列を作る、安定しない参照による不要な再描画
- 高コストな計算に React.memo、useMemo、useCallback がない
- ループの中で DOM のプロパティを読んでから書き込み、レイアウトのスラッシングを起こしている
- 画面の下部にある画像に loading="lazy" がない

### ページネーションの欠如
- 結果が無制限に返るリスト系のエンドポイント(LIMIT もページネーションのパラメーターもない)
- データ量に比例して増えるのに、LIMIT のないデータベースクエリ
- ネストしたオブジェクトを丸ごと埋め込んでいる API レスポンス(ID と、必要に応じた展開にすべき)

### 非同期コンテキストでのブロッキング
- 非同期関数の中での同期 I/O(ファイル読み込み、サブプロセス、HTTP リクエスト)
- イベントループベースのハンドラーの中での time.sleep() / Thread.sleep()
- ワーカーにオフロードせず、メインスレッドをブロックする CPU 集約的な計算
